PROTOTYPE: throwaway demo for the ticket Code fix whitespace behaviour. Not production code.

What does "Remove comment" delete?

When the Remove comment code fix deletes a comment, it also has to decide what happens to the spaces, indentation and line breaks around it. This demo lets you remove comments one at a time (a single fix) or all at once (Fix All), and shows exactly which characters go. Spaces show as · and line breaks as ↵. The question: do these rules give the result you'd expect in every layout, and does Fix All always give the same result as removing comments one by one?

Proposed rules

  1. Own line: if removing the comment leaves its line(s) empty, the whole line goes, line break included.
  2. Before code (only spaces to its left): the comment and the spaces to its right go, so the code keeps the comment's indentation.
  3. After code or between code: the comment and the spaces to its left go (to its right if there are none on the left). If that would glue two words together (return/*x*/value), one space is kept.
  4. Other lines are never touched, unless Tidy blank lines is on: then a removed block that sat between two blank lines (or at the top of the file) also takes one blank line with it.
  5. Fix All works out every deletion against the original text and merges them, using the same rules, as if each comment were already gone when classifying the others.
