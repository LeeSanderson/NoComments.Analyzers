# NOC0004: Do not use Razor comments

| Property | Value |
|---|---|
| ID | NOC0004 |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | None |

Message: `Razor comment: express the intent in code instead`

A Razor comment is a comment delimited by `@*` and `*@` in a Razor file (`.razor` or `.cshtml`). It is reported at its position in the Razor file, in markup and inside code blocks (`@code`, `@functions`, `@{ }`, and the bodies of `@if`, `@foreach` and similar blocks).

NOC0004 is reported at build time only. The IDEs don't show it while you edit a Razor file; it appears after a build.

## Why

Comments drift out of step with the code and markup they describe. Express the intent through component names, parameter names, types and tests instead.

## Examples

Reported:

```razor
@* Shows the basket total, including delivery *@
<p>@Total</p>

@code {
    @* recalculated on every render *@
    private decimal Total => Items.Sum(i => i.Price) + Delivery;
}
```

Two diagnostics: one for each `@* *@` comment.

Not reported:

```razor
<p>@BasketTotalIncludingDelivery</p>

@code {
    private decimal BasketTotalIncludingDelivery => Items.Sum(i => i.Price) + Delivery;
}
```

## Not reported

- **Directives.** Razor directives (`@page`, `@using`, `@inject`) and C# preprocessor directives are not comments.
- **Generated code.** NOC0004 reads the Razor file itself, not the C# the Razor generator produces, so the generator's scaffolding is never reported.
- **HTML comments** (`<!-- -->`). They are markup sent to the browser, not comments.
- **This form's boundary.** Text that only looks like `@*` inside a C# string (regular, verbatim, raw or interpolated) or inside a C# comment is not a Razor comment and is not reported as NOC0004. C# comments in a Razor file are reported as [NOC0001](NOC0001.md), [NOC0002](NOC0002.md) or [NOC0003](NOC0003.md). Code-behind files (`.razor.cs`, `.cshtml.cs`) are ordinary C# and contain no Razor comments.

## Code fix

None. Remove Razor comments by hand. The **Remove comment** fix of NOC0001 to NOC0003 does not apply to NOC0004, and `dotnet format analyzers` does not remove Razor comments.

## Suppression

NOC0004 is reported on the Razor file itself, which has no C# syntax tree, so only project-wide suppression works:

- A `.globalconfig` file: `dotnet_diagnostic.NOC0004.severity = none`.
- `<NoWarn>$(NoWarn);NOC0004</NoWarn>` in the project file.
- An assembly-level suppression with no target: `[assembly: SuppressMessage("Maintainability", "NOC0004")]`.

These do **not** work for NOC0004:

- `.editorconfig` severity, in any section (`[*]`, `[*.razor]` or `[*.cshtml]`).
- `#pragma warning disable NOC0004`, in a `.cs` file or in an `@code` block.
- Suppressing a single file or a single comment. There is no per-file control.

Under `TreatWarningsAsErrors`, or with NOC0004 in `<WarningsAsErrors>`, NOC0004 is reported as an error. There is no comment-based suppression syntax.
