# NOC0002: Do not use multi-line comments

| Property | Value |
|---|---|
| ID | NOC0002 |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | Remove comment |

Message: `Multi-line comment: express the intent in code instead`

A multi-line comment is a comment delimited by `/*` and `*/` that is not a documentation comment. Each comment is reported as one diagnostic that covers the whole comment, however many lines it spans.

## Why

Comments drift out of step with the code they describe. The compiler never checks them, so after a few changes they can say something the code no longer does. Express the intent through names, types and tests instead: those are checked on every build.

There are no built-in exemptions. License headers, commented-out code and inline notes such as `/* why */` are reported like any other multi-line comment.

## Examples

Reported:

```csharp
/*
 * Retries three times because the payment gateway
 * sometimes drops the first request.
 */
var result = await Send(request, /* attempts */ 3);
```

Two diagnostics: one for each `/* */` comment.

Not reported:

```csharp
const int PaymentGatewayAttempts = 3;

var result = await SendWithRetries(request, PaymentGatewayAttempts);
```

## Not reported

- **Directives.** `#region`, `#pragma`, `#nullable` and the other preprocessor directives are not comments.
- **Shebang lines** and **disabled `#if` text** (code inside an `#if` branch that is not compiled, even text that looks like `/* */`).
- **Generated code.** Files that Roslyn's generated-code detection classifies as generated (for example a `// <auto-generated/>` header, or a `.g.cs` or `.designer.cs` file name) are not analyzed. The one exception is a comment a person wrote in the C# of a Razor file (`.razor` or `.cshtml`): it is reported at its position in the Razor file, but the comments the Razor generator adds itself are never reported.
- **HTML comments** (`<!-- -->`) in Razor files. They are markup, not comments.
- **This form's boundary.** In a project that generates documentation (`GenerateDocumentationFile` is `true`), a `/** */` comment is a documentation comment and is reported as [NOC0003](NOC0003.md), not NOC0002. In a project that does not generate documentation, it is reported as NOC0002. The empty comment `/**/` is always a multi-line comment, in both modes. A Razor comment (`@* *@`) is [NOC0004](NOC0004.md).

## Code fix

The **Remove comment** code fix deletes the comment and tidies the whitespace it leaves behind. It does not reformat anything else.

- **Own line:** a comment on lines of its own is deleted together with those lines, so no empty lines are left.
- **Before code:** a comment with only whitespace to its left is deleted together with the spaces to its right, so the code keeps the comment's indentation.
- **After or between code:** a comment is deleted together with the spaces to its left (or to its right, when there are none on the left). A multi-line comment between code joins the two halves onto one line. If removing it would join two words, one space is kept.
- **Blank lines:** a block removed from between two blank lines also removes one of the blank lines. A block at the top of the file removes the blank lines after it. A block at the end of the file removes the blank line above it.
- `#region` names, braces and other formatting are not changed.

Before and after:

```csharp
Call(/* first */ a, b /* second */, c);
return/* no spaces */value;
int Other(int x) => x /* doubled
    below */ * 2;
```

```csharp
Call(a, b, c);
return value;
int Other(int x) => x * 2;
```

**Fix All** (document, project and solution) is supported. It removes all the targeted comments in one pass and gives exactly the same text as removing them one at a time.

In Visual Studio and VS Code with C# Dev Kit, the fix is offered for `.cs` files. The IDEs offer no code actions in Razor files. To remove C# comments from `.razor` and `.cshtml` files, run Fix All from the command line:

```shell
dotnet format analyzers --diagnostics NOC0002 --include-generated
```

`--include-generated` is needed because Roslyn sees the C# in a Razor file only through the generated code. The fix edits the Razor file itself, never the generated C#, and follows the same whitespace rules.

## Suppression

All the standard .NET suppression mechanisms work:

- `.editorconfig`: `dotnet_diagnostic.NOC0002.severity = none` (or `suggestion`, `warning`, `error`). Each rule's severity can be set separately.
- `#pragma warning disable NOC0002` and `#pragma warning restore NOC0002`.
- `[SuppressMessage("Maintainability", "NOC0002")]` on a member or type.
- A global suppression: `[assembly: SuppressMessage("Maintainability", "NOC0002", Scope = "type", Target = "~T:Widget")]`.
- `<NoWarn>$(NoWarn);NOC0002</NoWarn>` in the project file.

Under `TreatWarningsAsErrors`, NOC0002 is reported as an error. There is no comment-based suppression syntax.
