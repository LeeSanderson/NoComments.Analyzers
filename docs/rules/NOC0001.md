# NOC0001: Do not use single-line comments

| Property | Value |
|---|---|
| ID | NOC0001 |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | Remove comment |

Message: `Single-line comment: express the intent in code instead`

A single-line comment is a comment that starts with `//` and is not a documentation comment. Each `//` line is reported as its own diagnostic, at the exact span of the comment.

## Why

Comments drift out of step with the code they describe. The compiler never checks them, so after a few changes they can say something the code no longer does. Express the intent through names, types and tests instead: those are checked on every build.

No comment is exempt. License headers, `TODO` and `FIXME` notes, and tool directives written as comments (for example `// ReSharper disable ...`) are reported like any other single-line comment.

## Examples

Reported:

```csharp
public decimal Total(Order order)
{
    // Add 20% VAT to orders shipped in the UK
    if (order.Country == "GB")
    {
        return order.Net * 1.2m; // VAT
    }

    return order.Net;
}
```

Two diagnostics: one for each `//` comment.

Not reported:

```csharp
private const decimal UkVatMultiplier = 1.2m;

public decimal Total(Order order) =>
    order.ShipsToUk ? order.Net * UkVatMultiplier : order.Net;
```

## Not reported

- **Directives.** `#region`, `#pragma`, `#nullable` and the other preprocessor directives are not comments. Text after a `#region` or `#endregion` is part of the region name, so `#region Helpers // setup` is not reported. A `//` comment after `#if` or `#endif` is a comment and is reported.
- **Shebang lines** (`#!/usr/bin/env dotnet`) and **disabled `#if` text** (code inside an `#if` branch that is not compiled, even text that looks like `//`).
- **Generated code.** Files that Roslyn's generated-code detection classifies as generated (for example a `// <auto-generated/>` header, or a `.g.cs` or `.designer.cs` file name) are not analyzed. The one exception is a comment a person wrote in the C# of a Razor file (`.razor` or `.cshtml`): it is reported at its position in the Razor file, but the comments the Razor generator adds itself are never reported.
- **HTML comments** (`<!-- -->`) in Razor files. They are markup, not comments.
- **This form's boundary.** In a project that generates documentation (`GenerateDocumentationFile` is `true`), a `///` comment is a documentation comment and is reported as [NOC0003](NOC0003.md), not NOC0001. In a project that does not generate documentation, each `///` line is reported as NOC0001. A comment that starts with four or more slashes (`////`) is always a single-line comment, in both modes.

## Code fix

The **Remove comment** code fix deletes the comment and tidies the whitespace it leaves behind. It does not reformat anything else.

- **Own line:** a comment on a line of its own is deleted together with its line, so no empty line is left.
- **Before code:** a comment with only whitespace to its left is deleted together with the spaces to its right, so the code keeps the comment's indentation.
- **After or between code:** a comment is deleted together with the spaces to its left (or to its right, when there are none on the left). If removing it would join two words, one space is kept.
- **Blank lines:** a block of comment lines removed from between two blank lines also removes one of the blank lines. A block at the top of the file removes the blank lines after it. A block at the end of the file removes the blank line above it.
- `#region` names, braces and other formatting are not changed.

Before and after:

```csharp
var total = price * quantity; // includes tax
```

```csharp
var total = price * quantity;
```

**Fix All** (document, project and solution) is supported. It removes all the targeted comments in one pass and gives exactly the same text as removing them one at a time.

In Visual Studio and VS Code with C# Dev Kit, the fix is offered for `.cs` files. The IDEs offer no code actions in Razor files. To remove C# comments from `.razor` and `.cshtml` files, run Fix All from the command line:

```shell
dotnet format analyzers --diagnostics NOC0001 --include-generated
```

`--include-generated` is needed because Roslyn sees the C# in a Razor file only through the generated code. The fix edits the Razor file itself, never the generated C#, and follows the same whitespace rules.

## Suppression

All the standard .NET suppression mechanisms work:

- `.editorconfig`: `dotnet_diagnostic.NOC0001.severity = none` (or `suggestion`, `warning`, `error`). Each rule's severity can be set separately.
- `#pragma warning disable NOC0001` and `#pragma warning restore NOC0001`.
- `[SuppressMessage("Maintainability", "NOC0001")]` on a member or type.
- A global suppression: `[assembly: SuppressMessage("Maintainability", "NOC0001", Scope = "type", Target = "~T:Widget")]`.
- `<NoWarn>$(NoWarn);NOC0001</NoWarn>` in the project file.

Under `TreatWarningsAsErrors`, NOC0001 is reported as an error. There is no comment-based suppression syntax.
